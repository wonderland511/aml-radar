# AML-радар: отслеживание и предсказание волн покраски кошельков

Пять слоёв мониторинга, от самого запаздывающего к самому раннему. Только stdlib
Python 3.8+, никаких зависимостей, всё крутится на любом VPS за $4.

---

## Главное, что надо понять до установки

Волны покраски приходят **не из OFAC**. Реальная цепочка:

```
взлом / скам
     ↓  часы
атрибуция аналитиками (Chainalysis, TRM, Elliptic)   ← вот здесь кошелёк уже "красный"
     ↓  1–3 суток
отмыв через миксеры и instant-обменники
     ↓
горячие кошельки этих обменников тухнут
     ↓
твой вывод оттуда получает косвенную экспозицию
     ↓
биржа тормозит депозит
     ↓  недели–месяцы, если вообще
адрес попадает в OFAC SDN
```

OFAC стоит в самом конце. Значит, окно для реакции — те самые **24–72 часа**
между взломом и протуханием обменников. Ловит его `hacks_radar.py`, а не
`ofac_radar.py`.

Второе: **скоринг ретроактивен**. Адрес, чистый сегодня, через месяц может
стать грязным за ту же самую старую транзакцию — вендор дообогатил кластер.
Поэтому нужна не разовая проверка, а журнал проверок с датами.

## Шаг 1. Telegram-бот

1. `@BotFather` → `/newbot` → получаешь токен вида `123456:AAE...`
2. Создай приватный канал, добавь бота админом.
3. Узнай `chat_id`: напиши в канал что-нибудь и открой
   `https://api.telegram.org/bot<ТОКЕН>/getUpdates` — нужен `chat.id`
   (у каналов он отрицательный, вида `-100...`).

## Шаг 2. Ключи API

- **Etherscan V2** — обязателен для `exposure_watch.py`.
  Регистрация на etherscan.io → API Keys. Один ключ покрывает 60+ EVM-сетей
  через параметр `chainid`, V1-эндпоинты отключены с 2025 года.
  Бесплатный тариф — 5 запросов/сек, этого хватает с запасом.
- **TronGrid** — опционален, без ключа работает с урезанным лимитом.
  Нужен, если держишь USDT-TRC20 (а его держат почти все).

## Шаг 3. Установка

```bash
git init radar && cd radar          # или просто распакуй папку
cp config.example.json config.json
chmod 600 config.json               # там токены — права строго 600
nano config.json
bash install.sh
```

Заполни в `config.json`:

- `telegram.token`, `telegram.chat_id`
- `etherscan_api_key`
- `my_wallets` — все свои адреса. Для EVM указывай `chainid`
  (1 = Ethereum, 56 = BSC, 137 = Polygon, 42161 = Arbitrum, 8453 = Base,
  10 = Optimism). Для Tron `"chain": "trx"` без chainid.
- `watch_exchangers` — **вот это самое ценное поле**. Адреса горячих кошельков
  обменников, которыми ты пользуешься. Где взять: открой свои прошлые выводы
  и посмотри адрес отправителя — это и есть их хот. У обменника их обычно
  несколько, добавляй все, что видел, и по каждой сети отдельно.
- `hack_alert_threshold_usd` — порог. $5M — разумный старт. Ниже $1M ставить
  не советую, зашумит.
- `rss_feeds` — см. шаг 5.

`install.sh` сделает baseline-прогон. **Первый запуск каждого радара алертов
не шлёт** — он только запоминает текущее состояние. Иначе ты бы получил в
телегу 500 адресов из SDN и десять лет истории взломов.

## Шаг 4. Cron

`install.sh` предложит прописать сам. Вручную — `crontab -e`:

```cron
*/20 * * * *  cd /opt/radar && python3 hacks_radar.py         >> state/radar.log 2>&1
*/30 * * * *  cd /opt/radar && python3 exposure_watch.py      >> state/radar.log 2>&1
7    * * * *  cd /opt/radar && python3 ofac_radar.py          >> state/radar.log 2>&1
23 */6 * * *  cd /opt/radar && python3 opensanctions_radar.py >> state/radar.log 2>&1
0    9 * * 1  cd /opt/radar && python3 aml_journal.py due     >> state/radar.log 2>&1
```

Минуты 7 и 23 вместо 0 — чтобы не долбиться в API одновременно со всем миром.

## Шаг 5. Ускоряем опережающий слой

DefiLlama структурирован, но публикует инциденты с задержкой в дни. Минутную
скорость дают X-аккаунты: **PeckShield, SlowMist, Cyvers, BlockSec Phalcon,
Lookonchain**. Бесплатного X API нет, поэтому:

1. Заведи RSS-мост (RSSHub self-hosted, rss.app, siftrss) на эти аккаунты.
2. Получившиеся URL положи в `config.rss_feeds`.
3. `rss_keywords` уже настроены на hack / exploit / drained / seized / rug.

Альтернатива без RSS: у SlowMist и PeckShield есть публичные Telegram-каналы —
можно форварднуть их в свой канал руками и читать глазами. Менее красиво, но
работает с нулевой настройкой.

## Шаг 6. Baseline своих кошельков

Один раз, сразу после установки:

```bash
python3 aml_journal.py add-wallet --chain eth --address 0xТВОЙ --label "основной"
python3 aml_journal.py add-wallet --chain trx --address TТВОЙ --label "usdt"
```

Затем прогони каждый адрес через **два независимых скоринга** и запиши
результат. Два, а не один: Chainalysis, TRM, Elliptic и Crystal регулярно
расходятся в оценке одного и того же адреса, и биржа может смотреть не тем
вендором, что ты.

```bash
python3 aml_journal.py record --address 0xТВОЙ --vendor chainalysis \
        --score 2 --verdict clean --note "прямых нет, 2 хопа чисто"
python3 aml_journal.py record --address 0xТВОЙ --vendor trm \
        --score 5 --verdict low --note "косвенка через биржу, норма"
```

При каждом крупном поступлении фиксируй происхождение:

```bash
python3 aml_journal.py add-receipt --address 0xТВОЙ --source "ОбменникX" \
        --txid 0xabc... --amount "1500 USDT" --note "обмен с карты, чек в архиве"
```

## Что делать по каждому типу алерта

### 🚨 Новый взлом ≥ порога (`hacks_radar`)
Это предупреждение, а не происшествие. Ближайшие **48–72 часа**:
- Не выводить через instant-обменники и свопы без KYC.
- Если планировал заводить на биржу — подожди, заведи после окна.
- Через 3–4 дня прогони AML по адресам обменников, которыми пользуешься.

### ⚠️ Обменник ловит грязь (`exposure_watch`, жёлтый)
На их хот пришли средства с помеченного адреса. Их выдачи в ближайшие дни
будут нести косвенную экспозицию. Не выводить через него, пока не остынет.
Проверить, не выводил ли ты оттуда за последние сутки.

### 🛑 Прямая экспозиция на твоём кошельке (`exposure_watch`, красный)
Худший случай — прямой хоп, его видит любой скоринг.
- Средства **не двигать**. Особенно не отправлять на биржу: там сработает
  на депозите, и разговор пойдёт уже с их комплаенсом.
- Зафиксировать tx, дату, отправителя.
- Прогнать полный отчёт двумя вендорами, сохранить.
- Дальше — вопрос происхождения. Если это оплата от контрагента, поднимай
  переписку и документы; они и будут аргументом.

### 🟠 Новые адреса в мировых санкциях (`opensanctions`)
Средний приоритет. Прогнать AML по своим в течение суток.

### 🔴 Новые адреса в OFAC (`ofac_radar`)
Формальное подтверждение того, что аналитики знали давно. Плановая
перепроверка. Полезно как маркер в журнале: «на эту дату волна была».

### 🟢 Делистинг
Тоже сигнал: средства, привязанные к снятому адресу, могут переоцениться в
плюс. Tornado Cash сняли с SDN в 2025-м, и это поменяло статус многих
кошельков.

## Еженедельная рутина

Понедельник, cron дёргает `aml_journal.py due`:

```
🔔 За 3 дня сработало триггеров: 2
   [2026-08-18] hack: 1 инцидентов ≥$5,000,000
   [2026-08-19] ofac: +12 адресов в SDN
   → перепроверять ВСЁ, не только просроченное.

К перепроверке: 3 из 4
  eth   0x....  основной   последний скан: 2026-08-11
```

Перепроверяешь, записываешь через `record`. Если скоринг вырос, журнал сам
это подсветит:

```
⚠️  Скоринг вырос: 2.0 → 41.0 (+39.0) с 2026-08-11.
    Ретроактивная переоценка — разбирайся, какое старое поступление подтухло.
```

Именно за этим и нужна история: ты видишь **когда** адрес испортился, и можешь
сопоставить дату с журналом поступлений, чтобы найти виноватую транзакцию.

## Когда прилетела заморозка

```bash
python3 aml_journal.py report --address 0xТВОЙ
```

Отдаёт JSON-пакет: история поступлений с источниками и txid + вся хронология
проверок. К нему приложи скриншоты отчётов вендоров и чеки обменников. В
переписке с комплаенсом работает ровно одно: показать происхождение средств и
то, что на момент получения адрес был чистым по общедоступному скорингу.

## Гигиена, которая снимает половину проблемы

Радар — это детектор, а не броня. Броня — это структура кошельков.

- **Не смешивай потоки.** Отдельный адрес под каждый источник. Одно грязное
  поступление в общий кошелёк красит весь остаток; отдельный адрес
  локализует ущерб одной коробкой.
- **Прослойка между обменником и биржей.** Не заводи на биржу напрямую то,
  что вышло из instant-свопа.
- **Храни чеки.** Дата, txid, обменник, скриншот чистого скоринга на момент
  получения. Это единственное, что имеет вес постфактум.
- **Проверяй ДО приёма, а не после.** Если контрагент присылает адрес
  отправителя заранее — прогони его до сделки. Дешевле, чем разбираться потом.

## Диагностика

| Симптом | Причина |
|---|---|
| `распарсили 0 адресов` | OFAC поменял формат. Чинить `ADDR_RE` в `ofac_radar.py` |
| `грязное множество почти пустое` | Не прогнаны слои 1–2. Запусти их первыми |
| `You are using a deprecated V1 endpoint` | Старый ключ/URL Etherscan, нужен `/v2/api` + `chainid` |
| Тишина сутками | Так и должно быть. Проверь живость: `tail state/radar.log` |
| Телега молчит, в логе «сообщение потеряно» | Бот не админ в канале или `chat_id` без `-100` |

Раз в месяц загляни в `state/radar.log`. Молчащий радар и сломанный радар
выглядят одинаково — это главная ловушка любого мониторинга.

## Лицензии и лимиты

- OFAC Sanctions List Service — публичные данные, без авторизации и лимитов.
- OpenSanctions — бесплатно для некоммерческого использования; для бизнеса
  нужна лицензия на данные, см. opensanctions.org/licensing.
- Etherscan — 5 rps на бесплатном ключе. Скрипт сам держит паузы.
- DefiLlama — свободный публичный API без ключа.
